## 2026-10-29 — Day 4: the evidence layer, the judge, and both suites rebuilt

**Starting point (verified):** the frozen spec's skeleton — 29/29 tests green, offline demo running — with an honest defect list from a three-scout recon: non-atomic state persistence; nodes in-flight at a crash orphaned on resume; governance opt-in by construction (an empty instrument panel passed); worker artifacts grading themselves; costs self-reported by the measured party; an unhashed audit log ("append-only by politeness"); a "revise" verdict that silently completed the node; and a grader that accepted a NaN score and returned a NaN grade (confirmed by hand before any new code was written).

**Built today:**
- **Grader integrity:** finite-value validation as a posture at the grader boundary — scores, rubric weights, and aggregations reject NaN/inf/non-numeric by raising. Property tests over generated invalid inputs: 100% raise, zero graded totals.
- **Durable task graphs:** atomic state saves (temp + fsync + rename + directory fsync, schema-versioned); resume semantics with per-node dispositions (RUNNING requeues with an attempt counter and cap; FAILED is terminal and named; BLOCKED re-evaluates when its approver attaches); a guarded status lifecycle. Proven at the process level: 20 SIGKILL trials, 20/20 clean resumes, each node's effect recorded exactly once, zero corrupted state files.
- **Governance by construction:** a production constructor that requires a non-empty instrument panel, a rubric, and a gatekeeper; the ungoverned configuration survives only as a named test-only path (it is Suite B's control arm). Grading is no longer per-artifact opt-in; gate action classes are coerced and validated at the boundary (a case-drifted "SPEND" reaches the human gate, not the auto-approve path); gate authorization fails closed on exceptions and malformed requests — deny plus receipt, never a crash; an audit-write failure is record-or-halt.
- **"Revise" made true:** revise-band verdicts requeue the node with an attempt cap; exhaustion escalates.
- **Independent judge:** a separate caller (a different model variant than the worker), one criterion per call, reason-before-score, anchored exemplars, identified by a content-hash pin, responses cached, unparseable scores rejected fail-closed, self-grading refused at construction. The demo crew now grades entirely through the judge — worker artifacts carry no scores anywhere.
- **Receipts:** the audit log is now a hash-chained record (sequence + prev-hash + entry hash) with signed Merkle checkpoints on the E5 decision-receipt schema (signed in-repo by a development HMAC signer — its keyid discloses itself in every checkpoint; production graduates to the issuer's Ed25519 signer), gate receipts recording effect axes; an offline verifier proves a fresh log and detects both mid-log edits and tail truncation.
- **Cost as an instrument:** spend is metered at the transport from real usage, priced per model, tracked per lane against a canonical-lane ceiling ($40 planning target, $60 hard stop); worker-reported cost is advisory only.
- **Suite A rebuilt:** 12 remedy-design scenarios in three tiers (clear / trade-off / trap), hidden gold stakeholder lists, one-fact-flip twins, scorer probes (style twins, padding, order permutation, hedge case). 36 hand-authored reference proposals (strong / mediocre / fluent-but-wrong per scenario) prepared for the calibration key; calibration statistics (weighted κ per criterion with intervals, verdict-band κ, Spearman ρ) implemented and validated on known-agreement data.
- **Suite B rebuilt (the coin-flip simulator was deleted):** 10 real tasks executed through the runner over an assertable world-state, graded by final-state predicates; a deterministic fault manifest (crash / omission incl. timing subspecies / value) whose hash prints in every report; drift defined operationally — a run claiming completion while its final-state assertion fails. **First frontier (360 runs, identical manifests): governed arm drift 0, ungoverned arm drift 30** — with the cost printed beside it (completion 0.333 governed vs 0.667 ungoverned). Every drift event traced to a value fault in its manifest.
- **Corrections of record:** model IDs pinned to the real catalog (`muse-spark-1.3`, `muse-wonder-1.0`, `muse-image-1.0`, `sam-3.1`, `meta/muse-glimmer-30b`); `muse-wonder-full` is not an API model and was removed (see ERRATA.md). The transport runs dual-lane: the Meta Model API is canonical for Spark/Wonder; NVIDIA's Glimmer is the dev/overflow eval lane (entitlement test-called successfully today).

**State at end of day:** 154 tests passing, 0 failing. Golden-run check: the demo's report output is byte-identical across clean runs. The repository was created today (private during the build; it goes public before the submission, as the rules require).

**Next:** live transport wiring when the team's API access lands (everything above runs offline today); calibration of the judge against the hand-scored key; the golden freeze and submission package ahead of Nov 4, 12:00 PM ET.

## 2026-10-29 (later) — Calibration key approved

The 36-reference calibration key was draft-scored by the team's lead, reviewed by the project owner, and approved with one amendment: the A07 mediocre reference (full customer refunds and prospective disclosure, but no report to the regulator) is scored **revise**, not pass — full restitution without regulator notification does not pass. The amended key validates clean and its verdict bands separate exactly: 12 pass / 12 revise / 12 fail across the strong / mediocre / fluent-but-wrong tiers. A zero-cost dry-run of the calibration statistics against a stand-in judge was recomputed against the approved key: the judge ranks remedies well (Spearman ρ 0.910) but reads two criteria — reversibility and precedent consistency — materially lower than the key (κ 0.200 / 0.061), so the dry-run gate fails and names its own fix: strengthen those two criteria's anchored exemplars before the calibration run of record against the production judge.

## 2026-10-29 (later) — Correction: T3 kill-trial effect accounting

The Day-4 entry above says the kill/resume proof ran "20 SIGKILL trials, 20/20 clean resumes, each node's effect recorded exactly once." The 20/20 described the harness's **append-log accounting**, and that accounting was racy: the trial worker records an effect in two steps — write the node's `.effect` file, then append to `effects.log` — and its idempotent-return path on resume does not re-log. A SIGKILL landing between the two steps leaves an effect that landed exactly once permanently unlogged, and the harness assertion, which counted the append-log, failed intermittently (observed: full suite 153 passed / 1 failed; T3 standalone failed 2 of 4 runs) while every product invariant held — graph complete, zero corrupted state files, no duplicate effects. An earlier harness fix (waiting for the state file before killing) was real but addressed a different, first race; this was a second race behind it.

**Correction:** the harness now asserts exactly-once from the `*.effect` files themselves — the durable record of an effect having landed — not from the append-log (commit `cd92988`; harness only, no product code changed; the worker's idempotent-return semantics deliberately unchanged, since re-logging on resume would trade this race for a double-count). Stability, measured after the fix in this environment: **T3 kill-resume test 30/30 consecutive passes** (each pass is the full 20-trial gate) and **full suite 154 passed on 3 consecutive runs** (16.7s / 17.9s / 16.8s). The durability claim itself — resume completes the graph, each effect lands exactly once, state files never corrupt — is unchanged and now measured from the record that actually carries it.
